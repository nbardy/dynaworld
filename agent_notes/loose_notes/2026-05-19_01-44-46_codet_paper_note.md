Key takeaways:
    CodeT makes generated tests a selector signal rather than final truth. It
    generates both code candidates and tests, builds a candidate/test execution
    matrix, groups candidates by pass vector, and ranks consensus sets by test
    support plus sibling-candidate support.

    This corrects the largest-cluster weakness from AlphaCode-style selection:
    many trivial wrong candidates can agree with each other. The selector should
    score both how many tests a group passes and how many candidates support the
    same behavior.

Design implications:
    The first `alpha_evolve` implementation should include generated probe
    postprocessing, candidate/probe matrices, consensus scoring, toxicity
    audits, and selector ablations. Generated tests are useful as evidence, but
    hidden repo gates remain the promotion truth.
