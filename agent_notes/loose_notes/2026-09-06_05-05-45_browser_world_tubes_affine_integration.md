# Browser World Tubes: replace the renderer, retain the application

User authorized replacing the flawed Sol backend and fully integrating browser
learning/rendering for speed. No new goal, agents, native build, cloud run,
publication run, commit, deployment, or unrelated deletion was requested.
Many unrelated research files and a later `tests/auditInitializationUnits.mjs`
were already dirty or changed concurrently; they were left alone.

## Replaced

The previous untracked `trainerWebGpuWorldTubes.js` subclass changed a temporal
gate in 3DGS shaders. It was a valid sliced SPD4 representation but not the
project's UVT renderer. Replaced that file and its weak standalone smoke in
place. Removed Sol's mode-2 branches from the ordinary 3DGS training/rendering
shader; its only remaining change is schema validation against the receiving
trainer's expected contract. The existing tiled and sampled controls remain.

## Implemented

- Full conditional-block SPD4 world chart in the existing 24-float layout:
  center at t=.5, half-velocity, mean time/log temporal sigma, rotated spatial
  covariance, color and opacity. Harmonic/material-mixture slots are reserved.
- Per-atom pinhole linearization at mean time, exact affine UVT marginal and
  conditional depth mean/variance; explicit peak-preserving splat opacity.
- Analytic reverse-mode compiler generated from a small scalar expression
  tape. Gradients flow into shared world parameters, never independent cameras.
- GPU full-interval spatial bins, sampled-ray stable conditional-depth sorting,
  source-over reverse replay, atomic float gradient accumulation and Adam.
  Compiles once per atom/camera/step, not once per requested time or ray.
- Uniform pixel/time MSE, up to 4,096 atoms, 192 rays and four train cameras.
  This differs from the tiled backend's L1/SSIM/full-image objective.
- Preview recompiles for orbit cameras; dense preview rays use exact depth
  peeling after a 64-candidate fast path. Preview resolution is capped at 144h.
- Actual worker selector, OffscreenCanvas, CPU heldout validation using UVT,
  global-time temporal paging, and parameter/Adam continuation.
- Disabled controls that do not apply, clarified learned temporal widths and
  persistence diagnostics; old sliced-SPD4 checkpoint schema rejected.

## Retained evidence

`web/dynaworld_browser_trainer/benchmark_results/2026-09-06_world_tubes_integration.json`
is a mechanical smoke, not a speed or public-quality result. The independent
fixture is generated by the canonical float64 `pushforward_world_atoms` plus
Torch autograd; a measurement-noise covariance pullback allows the unmodified
oracle API to represent the 0.3-pixel filter.

Apple WebGPU max RGB error: 1.288e-7; max world-gradient error: 4.999e-8 over
19 active scalar slots (quaternion has one redundant degree). Trace max error
7.271e-5 in large precision coefficients, within mixed relative tolerance.
64-step fixed-batch fixture loss: .054926 -> .021999. Preview/orbit error below
.001954 (RGBA8 quantization), exact parameter/moment restore, worker paging,
4x resolution continuation and heldout validation passed. Final Node suite:
205 passed, including the final diagnostic-family regression. No W&B:
this was an intentionally local mechanical test, not a benchmark training run.

The actual Coffee Martini SPA loaded World Tubes at 4,096 atoms, executed a
training step and a continuous run, and advanced temporal pages. It exposed a
pre-existing progressive preload bug: at prefetch time the coarse dataset was
already a streamed page, while the fine base was still the overview atlas.
The early assertion failed, and animation ticks repeatedly retried the rejected
promise even after pausing. Closed the isolated browser to stop that lane.
Fixed preload validation ordering (validate after selecting matching fine
frames), excluded in-flight page switches, and latched/paused transition
failures. The controlled worker continuation test is green; this final SPA
preload correction itself has NOT been rerun on the GPU.

## Blocker / next work

During investigation a separate Python process was found actively training
`experiments/continue_path_time_ablation.py ... --device mps` on this host.
It was not touched. Stopped further accelerator/timing work once identified.
The UI rate counters from the shared session are NOT speed evidence. A bounded
`replayCompiler` diagnostic flag exists to compare identical-world per-ray
recompilation against trace reuse; the alternate GPU branch remains untested
and no speed comparison was launched.

On a quiet GPU: rerun `worldTubesSmoke.html`, test the actual SPA progressive
transition and switch back to tiled then World Tubes, stress >64 contributing
preview tubes, and measure paired identical-world timing plus matched wall-time
quality against the existing browser backend. Do not claim faster training from
different ray budgets or objective functions. Nonlinear/projective interval
atlases, visibility event derivatives, retained fibers and adaptive growth
remain explicitly outside this affine browser subset.

Local server was `python3 -m http.server 8080 --bind 127.0.0.1`. Isolated browser
session was `agent-browser --session world-tubes`, using installed Chrome with
`--enable-unsafe-webgpu`; browser cache required a clean session to pick up
unversioned child module changes. Entry-point asset tags were bumped at handoff.
